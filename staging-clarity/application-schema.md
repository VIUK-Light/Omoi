# Omoi 質問データのスキーマ

この文書は `level1.json` から `level4.json` までの質問カードに共通する編集ルールです。カードは年齢、関係性、パックで出し分けません。どのカードも利用者が飛ばせます。

## 共通フィールド

| フィールド | 必須 | 意味 |
| --- | --- | --- |
| `id` | はい | 全Levelで重複しない固定ID |
| `level` | はい | 配置ファイルと一致する1〜4の整数 |
| `sensitivity` | はい | 難しさではなく、話す前に配慮が必要な度合い（1〜4） |
| `category` | はい | 下記18分類のいずれか |
| `topic` | はい | 具体的な論点。細かな分類や検索・編集用の軸 |
| `question` | はい | 画面に表示する問い |

`sensitivity` が高いことは、特定の答えが正しいことや、利用者を年齢で制限することを意味しません。話したくない問いは、どのLevelでも飛ばせます。

## Levelの意味

| Level | 役割 |
| --- | --- |
| 1 | 身近な経験から始められる短い入口 |
| 2 | 日常・集団・境界線を通して、意見の違いを安全に扱う橋渡し |
| 3 | 制度・社会・役割の判断を考える問い |
| 4 | 個人的な利害または倫理的なトレードオフを自分に置き換える問い |

Levelは対象者の属性ではありません。Level変更は、編集レビューで一覧を示し、承認を得てから行います。

質問・解説・追加削除・Level・分類・感度・視点・警告タグの変更は、対象ID、変更前後、理由と検証結果を示して最終確認を取ります。承認済みの範囲は再確認を求めずに反映します。目的と確認手順は [OMOI_PHILOSOPHY.md](../OMOI_PHILOSOPHY.md) を参照してください。

## 18の上位カテゴリ

`category`は、カードが主にどんな好み・感覚・経験・価値観や判断について話す問いかで選びます。登場する語句だけでは決めません。複数の分野にまたがる論点は、`topic`や背景解説に具体的に残します。Level 1の好みに対立を無理に加える必要はありません。

| ID | 名前 | 範囲と使い分け |
| --- | --- | --- |
| `self_and_values` | 自分・価値観 | 自分の好み、感覚、経験、大切にしていること、自分の捉え方。具体的な分野より自分自身の感じ方や基準が主題の問い。 |
| `relationships_and_communication` | 人間関係・コミュニケーション | 友人・恋人などとの関係、連絡、信頼、相手への伝え方、関係の境界。個人同士の関わり方が主題の問い。 |
| `family_and_care` | 家族・ケア | 家族の関係、子育て、介護、扶養、身近な人のケア。家族やケアを担う立場の関係・責任が主題の問い。 |
| `school_and_youth` | 学校・若者 | 学校生活、教育、若者を取り巻く関係や制度。学ぶ場や学校・若者の立場に固有の経験・判断が主題の問い。 |
| `work_and_economy` | 仕事・経済 | 働き方、雇用、職場、事業、仕事を支える経済政策。物価と雇用が衝突する場合も、雇用維持や働き手の利害が主題ならこの分類に置く。家計・買い物・税の負担は money_consumption_and_tax、公的給付の対象・配分は society_public_policy_and_environment を基本とする。 |
| `gender_sexuality_and_identity` | ジェンダー・性・アイデンティティ | 性別、性、性的指向、性自認、アイデンティティ、これらに関する社会的な扱いや境界。場所や制度の種類より性別・性・自己認識の扱いが主題の場合に使う。 |
| `health_and_disability` | 健康・障害 | 健康、障害、治療、医療、必要な配慮、生命や看取り。治療や健康・障害についての本人や社会の判断を扱う。研究への参加・研究利用への同意が主題なら science_research_and_uncertainty を基本とする。 |
| `technology_media_and_privacy` | 技術・メディア・プライバシー | 技術、AI、メディア、情報発信、個人情報、監視。技術の利用や情報の扱い、題材を問わない発信方法・メディアの責任が主題の場合に使う。 |
| `justice_safety_and_crime` | 司法・安全・犯罪 | 犯罪、処罰、司法、治安、被害への対応、安全を守る責任。災害時の避難や災害・重大事故の予防判断が主題の場合は climate_environment_energy_and_disaster を基本とする。 |
| `society_public_policy_and_environment` | 社会・公共政策・環境 | 生活保障、公的給付、社会保障の対象・配分、社会政策、国内の移住者支援や多文化の暮らし。給付の受給条件に合わせた行動も、給付制度が主題ならこの分類に置く。環境を含む既存IDは保持し、主題が環境・気候・防災の場合は climate_environment_energy_and_disaster を基本とする。 |
| `culture_religion_and_history` | 文化・宗教・歴史 | 文化、宗教、歴史、伝統、慣習、象徴の受け止め方。観光場面でも祈りの場や信仰上の習慣を守ることが主題ならこの分類に置く。政治的表現の自由が主題なら democracy_rights_and_participation を基本とする。 |
| `ethics_and_decision_making` | 倫理・意思決定 | 倫理的な基準、責任、公平、選択の仕方。特定の分野より、複数の場面に共通する倫理や判断基準そのものが主題の問い。 |
| `money_consumption_and_tax` | お金・買い物・税 | 家計、買い物、価格、契約、財産、税の負担。働き方・雇用は work_and_economy、公的給付は society_public_policy_and_environment に残す。 価格や所得が登場しても、雇用維持が主題なら仕事・経済、給付の対象・配分・制度への対応が主題なら社会・公共政策に分類する。 |
| `housing_community_and_transport` | 住まい・地域・交通 | 住まい、近隣の暮らし、公共空間、観光と住民生活、移動、地域インフラ。家族内の介護や運転の判断は家族・健康の分類を優先する。 道路の維持・交通供給が主題の場合を含む。重大な災害・事故を防ぐ予防的な制限や対応責任が主題の場合は環境・エネルギー・防災に分類する。 |
| `climate_environment_energy_and_disaster` | 環境・エネルギー・防災 | 気候、環境、資源、エネルギー、災害への備え、避難、復旧。主な論点が性別の扱いの場合は gender_sexuality_and_identity を優先する。 環境の危機を社会へ伝えて対処につなげる責任や、重大な災害・事故を防ぐ予防判断も含む。研究方法・証拠の妥当性自体が主題なら科学・研究、題材を問わない発信方法・メディアの責任が主題なら技術・メディア・プライバシーに分類する。 |
| `democracy_rights_and_participation` | 民主主義・市民参加 | 意思決定への参加、代表、投票、政治家の責任、政治的な表現の自由。対外関係や国防は international_peace_and_cooperation に分ける。 |
| `international_peace_and_cooperation` | 国際・平和・協力 | 国をまたぐ暮らしや交流、国際協力、国防、平和、外交、人権と対外関係。国内の移住者支援は従来の社会政策の分類を基本にする。 |
| `science_research_and_uncertainty` | 科学・研究 | 確かめ方、調査、証拠、不確実性、研究への参加、研究倫理。治療や健康についての判断は health_and_disability を優先する。 知ろうとする好奇心や確かめ方の好み、研究利用への同意も含む。環境危機への対処や周知の責任が主題なら環境・エネルギー・防災、一般の発信方法の責任が主題なら技術・メディア・プライバシーに分類する。 |

既存のカテゴリーIDと質問IDは保持します。分類変更や本文修正のために質問IDを付け直しません。`society_public_policy_and_environment`に`environment`が含まれていても、主題による分類を優先します。範囲の説明は編集判断の補助であり、既存カードを語句だけで一括して再分類する規則ではありません。

### 雇用・公的給付・家計の境界

- **雇用・働き手の利害**：仕事の維持、職場の人員削減、働き方が主題なら`work_and_economy`。物価への政策でも、`r6-03-01-l3`・`r6-03-01-l4`は物価と雇用の衝突や自分の仕事への影響が中心なので、この分類に残します。
- **公的給付**：支援の対象、所得基準、配分、受給条件に合わせる行動が主題なら`society_public_policy_and_environment`。`r6-03-02-l3`・`r6-03-02-l4`は給付の所得境界とその影響が中心なので、この分類に置きます。働く時間が登場することだけを理由に仕事へ、所得やお金が登場することだけを理由に家計へ移しません。
- **家計・消費・税の負担**：予算、買い物、貸し借り、価格、契約、財産、税負担が主題なら`money_consumption_and_tax`。具体的な雇用や公的給付の問いでは、上記の主題との使い分けを確認します。

### 環境・科学・発信・道路インフラの境界

環境危機への対処や周知の責任、研究方法・証拠の妥当性、一般の発信方法・メディアの責任、交通の供給は重なることがあります。カードの主題と、どの条件が判断に不可欠かを見て分類し、別の論点は`topic`と解説で追えるようにします。

| 主題 | 基本となる分類 | 境界の例 |
| --- | --- | --- |
| 環境危機を社会へ伝えて対処につなげる責任 | `climate_environment_energy_and_disaster` | `r6-06-06-l3`・`r6-06-06-l4`は環境の危機へ注意を促し、行動につなぐ公共的な判断を扱うので、この分類に置きます。指標の妥当性や見出しの責任も解説・topicに残します。 |
| 確かめ方、研究方法、証拠や不確実性の扱い自体 | `science_research_and_uncertainty` | 特定の環境対策より測定・研究の方法を選ぶことが中心なら科学・研究。診療記録を研究へ提供する同意も研究倫理として扱い、治療そのものの選択とは区別します。 |
| 題材を問わない発信方法・メディアの責任 | `technology_media_and_privacy` | 記事の見出しや情報の広め方そのものが中心なら、環境などの題材はtopicに残し、メディアの分類を使います。 |
| 災害・重大事故を未然に防ぐ予防判断と対応責任 | `climate_environment_energy_and_disaster` | `r6-06-03-l4`は道路陥没の危険に対して、不確かな段階で予防的な通行止めを決める責任が中心なので、この分類に置きます。 |
| 道路の維持、交通の供給、地域の移動や住環境 | `housing_community_and_transport` | 道路や交通という対象だけで防災に置きません。維持するサービスの範囲や地域の交通をどう整えるかが中心なら地域・交通を使います。 |

カテゴリーの件数や全Levelへの均等配置を目的にしません。相手の考えと理由を聞く入口になる自然な問いを優先します。現在の画面ではカテゴリーを選択肢として表示せず、質問はLevel内で無作為に選びます。分類の拡充は編集時に話題の偏りや不足を確かめる基盤であり、分類数だけで画面や抽選の幅が変わるわけではありません。

## Level 3・4の追加フィールド

Level 3とLevel 4では、共通フィールドに加えて次を必須にします。

| フィールド | 意味 |
| --- | --- |
| `perspective` | 問いの主な立場。`affected`、`actor`、`decision_maker`、`observer`のみ |
| `detail.text` | 結論を押し付けず、考えるための背景・対立・条件を説明する文章 |

具体的な立場が必要な場合は、主視点を増やさず任意の `role` に `parent`、`teacher`、`friend` などを記録します。Level 4では、`affected`・`actor`・`decision_maker`をそれぞれ20%以上に保ちます。

## 高リスクの内容

必要なカードだけに、任意の `content_warning` 配列を付けます。使える値は次の10種類です。

`sexual_violence`、`pregnancy_and_reproduction`、`infidelity`、`family_conflict`、`abuse_and_coercion`、`self_harm`、`medical_and_end_of_life`、`crime_and_punishment`、`discrimination_and_hate`、`privacy_and_surveillance`。

このタグは編集・検証用の情報です。個別の確認画面は追加せず、既存のLevel警告とスキップ操作を維持します。

## 検証

次を実行します。

```sh
node tools/verify-question-dataset.mjs --enforce-quality-targets
```

この検証は、JSON構文、ID一意性、重複質問、Levelと配置の一致、必須metadata、カテゴリ・警告値、L2の80件以上、L4の視点比率を確認します。構造検証の成功だけで、意味の一貫性、理解しやすさ、事実関係を確認したとは扱いません。文面と背景のレビューを併せて行います。
