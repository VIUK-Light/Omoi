# Omoi v3 プレビュー

このディレクトリは関係図や文章区切りの比較実験を保存しています。通常の v3 画面はリポジトリのルートです。質問文・場面文は共通で、補助文は v3 ブランチで編集した質問JSONを参照します。現行公開版は main に残しています。

既存の Omoi と並べて、v3 の関係図を確認するための静的プレビューです。重い問いをきっかけに、その場にいる人が自分の思いを話す体験を検証します。回答や会話内容を入力・保存する機能はありません。

## ローカルで開く

リポジトリのルートから実行します。

```sh
python3 -m http.server 4173 --bind 127.0.0.1
```

- [プレビュー入口](http://127.0.0.1:4173/preview/omoi-v3/preview.html)
- [図ありで開く](http://127.0.0.1:4173/preview/omoi-v3/preview.html?diagram=1)
- [図なしで開く](http://127.0.0.1:4173/preview/omoi-v3/preview.html?diagram=0)
- [汎用関係図デモ](http://127.0.0.1:4173/packages/relation-diagram/demo/index.html)

図の有無はレビュー用の表示設定です。元の問い、Level 3・4 の開始前の案内、答えずに進む、前の問い、終了を合わせて確認します。プレビュー内の[利用規約](terms.html)と、[現行公開版の利用規約](../../terms.html)は区別しています。

関係図は標準で非表示です。対応する質問の下の「関係図を表示」で開き、同じボタンで閉じます。次・前の問いや再読み込みでは閉じた状態に戻ります。`diagram=1` はこのボタンを使える比較モードで、自動展開の指定ではありません。`diagram=0` はボタンも図も表示しない元のUIとの比較用です。

図を開くと最初の場面を表示し、図の上の〈／〉で前後に移れます。浮気は「浮気したあと→相手に伝えるか」の2場面、血縁は「育ててきた→血縁がないと分かった→配偶者は前から知っていた」の3場面です。血縁の最後は発覚前から隠していた事実を示し、発覚後に隠し始めたとは扱いません。分かった親子関係も後の場面に残します。性別は「男性の場合／女性の場合」の並列比較なので「ケース」と表示し、時系列とは区別します。

自動再生や循環はなく、先頭・末尾では移れない方向のボタンを無効にします。閉じて開き直す場合や、次・前のカードから戻る場合は最初の場面に戻ります。図の場面切り替えでは、元の問い・場面文は変更しません。

血縁の最後の場面では、配偶者の枠内に「血縁なしを隠した」、子どもの枠内に「配偶者と別の人の子」を表示します。自分と配偶者の間は矢印やラベルのない線で結び、自分と子どもの線の左下には「育ててきた」「血縁なし」を表示します。文字の背景で線を隠さず、自分の枠だけを薄い背景色で示します。図には、重く見る価値の選択肢や追加の問い、設定されていない気持ちは置きません。

浮気は「一度だけ浮気した自分」から「浮気された相手」へ「話す？」を点線の矢印で示します。告白済み・相手は知らないなどの事実は補いません。性別は「交際相手→殴る→男性」と「交際相手→殴る→女性」を別々の行で表示し、同じけが・性別以外は同条件と明記します。加害側の性別や、それぞれの感じ方は設定しません。両方とも `pairs` 配置を使い、追加の問い返しや長い説明文を外しています。

Omoi固有の図データと配置指定の選択は `adapter.mjs`、描画は独立したコンポーネントです。血縁は `branches` の `direction: 'right'` と `rootId: 'self'` を使い、自分を左中央、配偶者を右上、子どもを右下へ配置します。人物名と短い関係だけを表示し、スマホや文字拡大時も左右二列を保ちながら、実測した文字の大きさに合わせて縦の余白を確保します。

プレビューの全画面は、端末の `prefers-color-scheme` に合わせてライト／ダーク表示を切り替えます。配色は `theme.css` で共通化し、要点・ヒント・背景・終了確認・規約にも適用します。関係図の文字・枠・線も同じ設定に追従し、表示中に設定が変わった場合も再読み込みは不要です。

汎用コンポーネントの入出力と組み込み方は [API.md](../../packages/relation-diagram/API.md)、単独のデモは [demo/index.html](../../packages/relation-diagram/demo/index.html) を参照してください。

## 問いの要点

`summary=1` は「問いの要点を見る」ボタンを使える表示です。要点自体は初期非表示で、見たいときだけ開きます。閉じる・次の問い・前の問い・再読み込みでは閉じた状態へ戻します。会話のヒント・背景と同時に開かず、必要な補助を一つずつ表示します。

会話AIの例は「決めること」「考える論点」の2項目の箇条書きです。論点は「AIとの親密な会話、事業の利益、友人関係への影響」とし、開発の動機や利用者の需要を断定しません。元の場面にある収益と利用者の行動の事実は、場面文で確認できます。

文章量や項目数は問いの複雑さに合わせ、3項目などの固定数や一律の文字数制限を品質基準にしません。文章・箇条書き・表・図・絵から、判断対象や前提を読み取りやすくする形式を選びます。要点のために全形式を使い分ける必要はありません。

会話AIの例（`r6-08-02-l4`）と、血縁・性別の計3問に内容を用意しています。血縁は「それでも」が指す状況を、性別は比較の前提を確認する補助です。浮気の例は問いだけで判断対象が伝わり、要点が同じ意味の繰り返しになるため設けません。AIの入口は `warning.html?sample=r6-08-02-l4&diagram=0&summary=1`。要点は `question-summary.mjs` で原文と照合し、未作成の問いや原文が変わった場合は表示しません。自動生成の推測で埋めることはありません。

指定のない表示と `summary=0` は従来の表示です。注意画面を経由して同じ質問を比較でき、次・前のカードでは内容を更新します。質問文・場面文、関係図の初期非表示、帰属・ライセンス表示は保持します。質問JSONの補助文は通常版と共通の編集済み内容です。

### 3つの補助機能の役割

- **問いの要点**：何を判断する問いか、どのような価値や論点を考えるかを整理する。
- **会話のヒント**：別の見方や、相手の理由を聞いて対話を深めるきっかけを示す。
- **問いの背景**：用語、現実の事例、関連する研究など、考えるための知識を説明する。外部の事実や研究は出典を確かめ、場面の設定と区別する。

要点へ追加の問い返しや背景解説を詰め込まず、それぞれの役割で内容を見直します。補助の説明を常時表示して区別することはしません。

### 要点の品質基準

**理解を助けるが、結論は誘導しない。考えるための補助であり、考えることの代わりにはならない。**

- 何をどうする問いかを先に定め、中心となる判断対象と、理解に必要な前提・論点を明確にする。
- シナリオにない事実、需要、属性、気持ちや意図を追加しない。原文の事実、本人の認識、未確定のことを区別し、時系列と並列比較を混ぜない。
- 特定の結論へ誘導する言葉や、開発の動機などの決めつけを避ける。中立に見せるために、場面で明示された重要な事実を打ち消したり、反対の事実を作ったりしない。
- 長さと項目数は複雑さに合わせる。複雑な場面の短い振り返りは残し、同じ情報を見出し・本文・図へ意味なく繰り返さない。
- 問いだけで判断対象が伝わり、説明を加えても理解を助けない場合は要点を設けない。
- 要点を読まなくても回答・対話できるようにする。元の問いと場面を読める状態にし、要点の閲覧を次へ進む条件にしない。
- 表は比較する項目と条件をそろえる。図は必要な人物・関係を省かず、言葉がどの線に属するか明確にする。同じ人物の位置や見た目を理由なく変えない。
- 絵は状況の理解に必要なものに限り、原文にない属性や感情を足さない。意味が伝わる代替文も用意する。
- 表示検証だけで理解しやすくなったとは判定しない。読んだ人が、何を決める問いなのかを説明できるかを確かめる。

公開前には、原文と照らして判断対象・前提・事実の範囲を確認し、特定の賛否を選ぶような書き方になっていないかを読む。項目数や画面上の収まりだけで文章品質の合格とはしません。

表示内容は `getQuestionSummaryContent()` のブロック配列で指定し、`summary-content.mjs` が開いたときだけ描画します。対応形式は `text`、`bullets`（項目ごとの任意ラベルと本文）、`table`（比較内容の説明・列見出し・行）、`diagram`（既存の図データと配置）、`image`（同じ配信元の画像と必須の代替文）です。閉じると図を含む内容を破棄します。形式に合わせて事実や結論を自動補完しません。

## 文章の区切りを比較する試作

血縁カードは、注意画面に `reading=chunks` を付けて開くと、元の場面文を意味ごとの3つのまとまりに分けます。言葉・順序・文字サイズ・色は変えず、まとまりの間に余白を置くだけです。「元の文章に戻す／場面文を区切る」で同じカードのまま切り替えられます。番号や時系列の矢印は付けません。

比較入口は `warning.html?sample=l4-relationship-002&diagram=0&reading=chunks`。`reading=original` なら文章をつなげた状態から比較できます。指定のない従来の表示には変更を加えず、図も標準非表示のままです。次・前・再読み込みではURLで指定した表示に戻り、通常カードでは切り替えを表示しません。原文が更新され、区切りと一致しない場合も原文をそのまま表示します。

この試作は「図を使う方が状況をつかみやすいか」を同じ内容で見比べるためのものです。表示の確認だけで理解しやすさが向上したとは判定しません。

新しい v3 独自部分は、ソース閲覧可能（source-available）の **Omoi v3 Noncommercial Attribution License 1.0** で提供します。これは PolyForm Noncommercial 1.0.0 を基に追加・優先条件を定めた独自ライセンスです。未変更の PolyForm や、商用利用可能なオープンソースとしては表示しません。許諾条件は、Part A と Part B を合わせた [LICENSE](LICENSE) 全体です。PolyForm の原文や URL だけを代わりのライセンスとして使うことはできません。

v3 独自部分の商用目的での複製、改変、再配布、別サービスでの提供、商用製品・サービスへの組み込みは許諾していません。公式サービスを使う許可と、独自のサービスへコードやデータを持ち込む許可は別です。

非商用の複製・改変・再配布には、次の両方が必要です。

1. 配布するソースやバンドルへ完全な `LICENSE` と該当する `NOTICE` を同梱し、VIUK-Light、[https://viuk-light.org/](https://viuk-light.org/)、継承元・第三者の表示を保持する。

ファイル内の表示だけでは UI の表示条件を満たさず、UI の表示だけでは `LICENSE`・`NOTICE` の同梱条件を満たしません。派生 UI の表示例です。

