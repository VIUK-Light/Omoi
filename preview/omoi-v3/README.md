# Omoi v3 表示比較

通常の v3 画面はリポジトリのルートです。このディレクトリには、問いの要点と文章の区切り方を比較する試作を残しています。関係図は検証用を含めて廃止しました。

重い問いをきっかけに、その場にいる人が自分の思いを話す体験を検証します。回答や会話内容を入力・保存する機能はありません。

## 開く

リポジトリのルートで起動します。

```sh
python3 -m http.server 4173 --bind 127.0.0.1
```

[表示比較の入口](http://127.0.0.1:4173/preview/omoi-v3/preview.html)から各サンプルを開けます。共有確認には本人限定の非公開プレビューを使います。

質問文・場面文は通常版と共通です。補助文も同じ編集済み質問JSONを参照します。内容の注意画面、次・前、パス、終了、ヒント、背景の操作を確認できます。端末のライト／ダーク設定に追従します。

## 問いの要点

`summary=1` は「問いの要点を見る」ボタンを使える比較モードです。要点自体は初期非表示で、見たいときだけ開きます。閉じる・カード移動・再読み込みでは閉じた状態へ戻します。ヒント・背景と同時に開きません。

比較用の内容を用意しているのは、会話AI（`r6-08-02-l4`）、血縁（`l4-relationship-002`）、性別（`gender-l3-009`）です。浮気（`relationship-009`）は問いだけで判断対象が伝わるため、要点を設けません。通常版の164問の要点とは、比較用データを区別しています。

AIの例は「決めること」「考える論点」の2項目の箇条書きです。原文にない需要、意図、感情を補いません。文章量や項目数を固定の品質基準にはしません。

入口の例は `warning.html?sample=r6-08-02-l4&summary=1`。指定のない表示と `summary=0` は比較用の元の表示です。元の問いが更新され、比較用内容の前提と一致しない場合は要点を表示しません。

`getQuestionSummaryContent()` のブロック配列を `summary-content.mjs` が開いたときだけ描画します。対応する形式は `text`、`bullets`、`table`、`image`。画像は同じ配信元に限り、代替文を必須にします。形式に合わせて事実や結論を補完しません。

## 文章の区切り方

血縁カードを `warning.html?sample=l4-relationship-002&reading=chunks` で開くと、元の場面文を意味ごとの3つのまとまりに分けます。言葉・順序・文字サイズ・色は変えず、まとまりの間に余白を置きます。「元の文章に戻す／場面文を区切る」で比較できます。

`reading=original` なら文章をつなげた状態から比較できます。通常カードや、原文が区切りと一致しない場合は切り替えを表示しません。次・前・再読み込みでは指定した表示に戻ります。

## 品質基準

**理解を助けるが、結論は誘導しない。考えるための補助であり、考えることの代わりにはならない。**

- 要点は判断対象と必要な前提・論点を整理する。ヒントは対話のきっかけ、背景は用語や確認できた知識を扱う。
- 原文の事実、本人の認識、未確定のことを区別する。設定されていない需要、属性、気持ち、動機を足さない。
- 問いの言い換えだけになる要点は設けない。同じ内容を複数の補助へ重複させない。
- 表は比較する項目と条件をそろえる。画像は理解に必要なものだけにする。
- 要点を読まなくても対話・スキップできる状態を保つ。
- 表示の収まりだけで理解しやすくなったとは判定しない。試用で、何を判断する問いなのかを説明できるか確かめる。
