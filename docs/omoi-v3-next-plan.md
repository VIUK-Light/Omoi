**現行のOmoiと公式説明を踏まえた基準（2026-11-07確認）**

- 今回のユーザーの説明と公式の[制作背景](https://viuk-light.org/omoi-details.html)を踏まえ、核は、日本で普段わざわざ話す機会の少ない重い社会問題や個人の選択を、カードをきっかけに話題にし、互いの思いを伝え合うことに置く。社会の問題を知ること、相手の考えを知ること、自分の思いを話すことを、排他的な製品方向の三択にはしない。
- [名前の意味・思想](https://viuk-light.org/omoi-concept.html)は、重い＝扱う話題、想い＝作った理由、思い＝その場で生まれる自分の考え、と説明している。問いの踏み込みと、その場にいる人が自分の言葉で答えることを保つ。
- [編集方針](https://viuk-light.org/omoi-editorial.html)に沿って、必要な題材名や「あなたならどうする？」を残す。重い問いを、望ましい対処法や制度の一般論に置き換えない。例えば現行の `relationship-009` の「相手に話す？」を、下記の旧案の「何をどう伝えるか」に変えると、話すか黙るかの判断を先に解消してしまうため、その変更は再検討する。
- 現行には既に、血のつながりがないと分かった子どもを育て続けたいかという問いや、男性が親密な相手から受けた暴力を相談する問いがある。v3の必要性を題材の追加だけで説明しない。
- 現行の画面は、具体的な場面と問いを中心に置き、必要なときにヒント・背景を開く。理由例を初めから並べる新案は、この中心体験をどう支えるかで評価し、本人の答えを先回りしないかも確認する。理由例や複数視点の表示を一律に禁止する判断にはしない。
- [Omoi for Series](https://viuk-light.org/omoi-for.html)のカードの重なり、白地、余白、短い色線は視覚表現の参考にできる。二つの代表的な回答理由を常設することは、forのカード表現から必然的に導かれる仕様ではない。
- 公開アプリのHTML・CSS・JavaScript・4つの質問JSONをHTTPSで取得し、作業コピー `3eeff5a` と一致することを確認した。画面の操作は取得したファイルのローカル表示で、スマホ・デスクトップの開始→話題選択→Level 4注意→問い→背景を確認した。公式カタログの掲載版は別に扱い、最新の質問正本と無条件に同一視しない。

**2問の編集案**

| 項目 | 校則 `support-006` | 浮気 `relationship-009` |
| --- | --- | --- |
| 関係の種類 | 同じ判断に対する意見の違い | 同じ出来事に関わる役割の違い |
| 問いの案 | 「靴下は白だけ」という校則に、理由を聞いても納得できない。ルールが変わるまでは守るべきだと思う？（現行の問いを使う） | 浮気した側は何をどう伝え、浮気された側は何を知ったうえで、これからの関係を考えたい？ |
| 一方の説明の案 | 守るべき：変わるまでは共通のルールを大切にしたい | 浮気した側：起きたことと自分の責任をどう伝え、相手が考えるために必要な情報をどう示すか |
| もう一方の説明の案 | 守らない選択もあり：納得できる理由があるかを大切にしたい | 浮気された側：何を知りたいか、どんな距離や時間が必要か、関係を続けるかどうかを自分で考える |
| 問い返しの案 | 守る側には「どんな場合なら、守らない選択も考えられる？」。守らない側には「その選択で、周りへの影響をどう考える？」 | した側には「相手がこれからを選ぶために、何を知る必要があると思う？」。された側には「今、知りたいことと、まだ決めたくないことは何？」 |

校則の関係ラベルは「ルールが変わるまで、どうする？」。浮気の関係ラベルは「同じ出来事に関わる二つの立場」とする。

未選択の案内は「気になる立場から考えてみよう。条件による考えや、別の見方も話せます。」。各立場の操作には「この立場で考える」と添え、選択中は「この立場で考えています」と表示する。同じ立場を押すと未選択の案内に戻る。問い返しは一度に一つ表示する。

浮気の例は、架空の場面として次の前提を置く。既存の「一度だけ浮気したら話すか」から、約束を破った後の伝え方と判断を両側から考える問いへ編集する。

| 表示 | 文面の案 |
| --- | --- |
| 共通の事実 | 二人は「ほかの人とは交際しない」と約束していた。／一方が、その約束を破って別の人とも交際した。 |
| まだ分からないこと | 浮気に至った経緯と、別の人との交際が続いているか。／浮気された側が既に知っていることと、二人の今後の希望。 |

これらはカードに設定する前提と未確定点を表す。経緯や気持ちを補って断定せず、問い返しでも未確定の内容を事実として扱わない。浮気された側に許すことや関係の継続を求めず、両側の表示が責任まで同じだと読まれないようにする。

背景解説は次の案に差し替える。

> 二人で決めた約束が破られた場面を、浮気した側と浮気された側から考える問いです。
>
> 浮気した側は、起きたことや自分の責任をどう伝え、相手が判断するための情報をどう示すかを考えます。浮気された側は、知りたいことや必要な時間・距離を確かめ、これからの関係を自分で考えます。
>
> 関係を続けるか、離れるか、まだ決めないかも含めて考えられます。

会話のヒントは「それぞれが大事にしたいことは、どこが同じで、どこが違う？」「まだ分からないことによって、考えが変わるとしたらどこ？」の2件にする。「配慮」「誠実」の用語と定義は現行のものを使い、公開前に新しい問い・背景・ヒントと合わせて文面を確認する。個人的な経験を話さず、架空の場面として考えられる表現にする。

**カード内の表示順**

1. 元の問い。
2. 共通の事実と、まだ分からないこと（浮気の例のみ）。
3. 関係ラベルと両方の立場。短い説明は常に表示する。
4. 未選択の案内、または選んだ立場の問い返し。
5. 既存のヒント・背景・次の問い・前の問い・終了の操作。

幅700px以上では両側を横に並べ、それ未満では上から順に並べる。共通事実と未確定点も、広い画面では横に、狭い画面では縦に置く。立場の表示順は固定する。対象カードでは質問領域の高さ制限と内部スクロールを外し、ページ全体を縦に読める形にする。片側を隠す切り替えや横スワイプは使わず、選択後も同じ順序を保つ。

**データ案**

既存カードに任意の `paired_views` を追加する。初回の形は次を提案する。

```json
{
  "paired_views": {
    "relation_label": "ルールが変わるまで、どうする？",
    "views": [
      {
        "id": "follow_until_changed",
        "label": "守るべき",
        "points": ["変わるまでは共通のルールを大切にしたい。"],
        "prompt": "どんな場合なら、守らない選択も考えられる？"
      },
      {
        "id": "consider_not_following",
        "label": "守らない選択もあり",
        "points": ["納得できる理由があるかを大切にしたい。"],
        "prompt": "その選択で、周りへの影響をどう考える？"
      }
    ]
  }
}
```

必要なカードだけ、同じオブジェクトに `shared_facts` と `unknowns` を文字列配列で追加する。浮気の例では両方を使う。一般的な状況説明の `scenario` と内容を重ねない。

浮気の例に追加する `paired_views` の案は次のとおり。問い・背景・ヒントは上記の文面に揃える。

```json
{
  "paired_views": {
    "relation_label": "同じ出来事に関わる二つの立場",
    "shared_facts": [
      "二人は「ほかの人とは交際しない」と約束していた。",
      "一方が、その約束を破って別の人とも交際した。"
    ],
    "unknowns": [
      "浮気に至った経緯と、別の人との交際が続いているか。",
      "浮気された側が既に知っていることと、二人の今後の希望。"
    ],
    "views": [
      {
        "id": "actor",
        "label": "浮気した側",
        "points": ["起きたことと自分の責任をどう伝え、相手が考えるために必要な情報をどう示すか。"],
        "prompt": "相手がこれからを選ぶために、何を知る必要があると思う？"
      },
      {
        "id": "affected",
        "label": "浮気された側",
        "points": ["何を知りたいか、どんな距離や時間が必要か、関係を続けるかどうかを自分で考える。"],
        "prompt": "今、知りたいことと、まだ決めたくないことは何？"
      }
    ]
  }
}
```

- `paired_views` がある場合はオブジェクト、`views` はちょうど2件。各 `id` はカード内で一意、名称・論点・問い返しは空でない文字列とする。
- `points` は空でない文字列配列。初回の文面は各立場1項目から始め、表示を見て長さを調整する。
- `shared_facts` と `unknowns` は任意。指定する場合は空でない文字列配列とする。
- 既存の `perspective` は主視点を表すメタデータとして別に扱う。二つの立場を表示するために値を増やしたり、Levelを変更したりしない。
- 読み込み時とデータ検証時の両方で構造を検証する。欠落は通常表示、不正な値は既存のエラー・再試行へ接続し、別カードの表示や選択を残さない。

**実装箇所と注意点**

| 箇所 | 変更する内容 |
| --- | --- |
| `question.html` | 両方の立場、共通事実・未確定点、問い返しの表示領域を用意 |
| `question.js` | `validateQuestions()` に構造確認、`showQuestion()` に表示と初期化、`showMessage()` に表示の消去を追加。選択の切り替え・解除を実装 |
| `question.css` | 対象カードの配置、短い色線、枠・余白・選択状態を追加。対象カードの質問領域は高さ制限と内部スクロールを外し、700pxを境に両側を横・縦に配置 |
| `level2.json` / `level4.json` | 対象2問の表示データと整合する文面を編集 |
| `QUESTION_DATA_SCHEMA.md` / `tools/verify-question-dataset.mjs` | 任意データの仕様と検証を追加 |
| `tools/question-flow.test.mjs` / `e2e/` | 新しい状態遷移、通常カードへの復帰、注意画面を経た表示、実際の配置を確認 |

選択にはネイティブのボタンと `aria-pressed` を使う。Tab・Enter・Spaceで操作でき、枠や表示でも選択が分かるようにする。現在の質問領域は `aria-live`・`aria-atomic` を持つため、切り替えのたびに問い全体を読み上げ直さない構成を選び、選択状態と問い返しを確認できるようにする。

問いの文字数だけで配置を決める現在の処理に、両側の説明があるカードの配置を分けて追加する。対象カードはページ全体でスクロールするため、質問領域内のスクロール案内は出さない。通常カードに戻ると現在の配置とスクロール案内に戻す。

**受け入れ条件**

| 観点 | 確認すること |
| --- | --- |
| 初期表示 | 元の問い、両方の立場名と短い説明を、展開操作なしで同じカードから読める。タブや選択で片側を隠さない |
| 表示の意味 | 同じカードに両側を常設することを必須とする。全文章を必ず一画面に収める条件とは分ける |
| 選択 | 左側→右側→解除で、強調と問い返しだけが変わる。選択で他方の説明や共通事実・未確定点を消さない |
| 状態の初期化 | 次へ、前へ、再読み込み、エラー表示の後に前の選択が残らない |
| 通常表示 | 両側表示のないカードに移ると、追加の空枠・問い返し・余白が残らない |
| 既存の操作 | パス、前へ、終了確認の確定・取消、ヒント、背景、読み込み失敗からの再試行が使える |
| 注意画面 | 既存のレベル選択からLevel 3・4の注意画面を経て進める。試用・検証用の表示固定でも、この導線を迂回しない |
| スマホ 360×800 | 横スクロールや文字の重なりがない。短い説明を読み比べられ、必要な縦スクロールが分かる。操作対象は44px以上を目安にする |
| タブレット 768×1024 | 同じ問いを囲んで両側を比較でき、選択の違いが分かる |
| 投影相当 1280×720 | 問い・両側の短い説明・主要な操作が収まる配置を確認。終了操作が下端で欠けない。教室後方からの読みやすさは実際の投影で別に確認 |
| キーボード等 | フォーカスが見え、操作順が自然で、選択状態を色だけに頼らず判別できる |

スマホで比較しにくい場合は、上下配置を保って文面と余白を調整する。文字を小さくするだけで収めない。投影で共通事実などが収まらない場合も、先に重複する文面を整理して再確認する。

検証ではブラウザのデータ差し替えで対象カードを固定し、本番のシャッフルやURL仕様を変えない。既存のLevel 4再読み込みだけで注意画面に戻るとは仮定せず、試作の挙動と既存URLの挙動を分けて記録する。選択状態が消えることは、どちらの場合も確認する。

```sh

node tools/verify-question-dataset.mjs --enforce-quality-targets --summary

```

新しいテストは、両側が残ること、切り替え・解除・初期化、通常カードへの復帰、不正データからの再試行を中心にする。画面の寸法だけでは実際の読みやすさを判断できないため、3サイズの目視確認も記録する。出典なしの既存警告661件は引き継ぎ資料の数値として扱い、実装前後の実測で増減を確認する。

**試用案**

最初の試用は、友だち2組、小グループ2班、投影1回を目安にする。参加可能な場面から始め、実施できなかった場面は未確認として残す。校則の問いを共通の入口にし、浮気の例は注意画面を読んで扱うことを選んだ参加者との別枠で確認する。

| 場面 | 進め方 | 主に見ること |
| --- | --- | --- |
| 友だち | 一人がスマホを操作。問いを読んで自由に会話し、必要に応じて立場を切り替える | 説明を読むだけで終わらず、相手自身の理由を尋ねるきっかけになるか |
| 小グループ | 班の一人がタブレットを操作。参加者は選択と違う意見や条件付きの考えも話せる | 操作者の選択が班全体の答えだと受け取られないか。ほかの人も発言できるか |
| 投影 | 進行役が操作し、表示後に会話へ移る | 後方から読めるか。選択が多数決に見えないか。操作のために会話が途切れないか |

初めは操作の補助だけで進める。理由を聞くよう進行役が促した場合は、その介入を記録し、自発的に起きた会話と分ける。

記録するのは、①画面上の二つの説明以外の理由が出たか、②相手に理由を尋ねる問いと返答があったか、③相手が大事にしていることを自分の言葉で言い直せたか、④二択や立場の選択で戸惑ったか、⑤読みやすさ・操作・パス・終了で詰まったか。発言内容の保存を前提とせず、会話の様子と操作上の事実を観察メモに残す。

終了時には「相手が大事にしていたことは何だった？」「画面の二つ以外に、どんな考えがあった？」「話しやすかった箇所・話しにくかった箇所は？」を短く尋ねる。参加者の感想と観察者の解釈は分ける。

**試用後の判断案**

- **文面・配置を修正する**：二択を強制された、役割と責任が混同された、問い返しが結論へ誘導した、両側を読めなかった、という問題が見られた場合。解消してから追加する。
- **少数カードに広げる**：試した画面で操作が成立し、複数の組で相手の理由を聞く・言い直す場面が確認できた場合。次は意見の違い3問・役割の違い3問を候補に選び、問いとの適合と文面を一問ずつ確認する。
- **対話ガイドを再検討する**：両側は理解できても会話の始め方で止まる場合。問いを増やす前に、会話の進め方の支援を試す。
- **比較試用へ進む**：会話のきっかけが観察できた場合、次段階で通常カードとの比較を計画する。同じ問いの繰り返しや提示順の影響を避ける組み方にし、初回の少数試用だけで効果が実証されたとは判断しない。

試用後に残す成果物は、対象2問の確定版、実装したコミット、画面と回帰の確認記録、匿名の観察メモ、次に進める案と保留理由。初回の実装と、会話への効果の確認を別々に追える形にする。
