# 担当外レビュー

状態：未承認の追加案。各担当は自己レビューに加え、別担当の全文と背景を確認する。正本は編集しない。

## 確認する内容

1. 全問の問い・背景・追加理由を読み、Omoiが相手の感覚・経験・価値観・理由を知る入口になっているか確認する。賛否を問うカードも、同意や模範行動を要求していないか見る。
2. 主語、立場、判断対象、比較条件が明確か。L1/2の入口、L3の社会・役割、L4の本人の利害・倫理・意味が配置に合うか。
3. 既存の近い原文・背景と担当内の似た案を比較する。人物・物・数字・媒体だけの差替えが新しい問として数えられていないか。機械比較候補があれば、文面と背景で判断する。
4. 背景がその問いを補助するか。一方の立場だけを悪く固定していないか。架空条件と現実の制度・医療・調査の事実が混ざっていないか。資料の有無だけで正確だと判定しない。
5. 視点・感度・警告タグが主題と整合するか。L4の「自分」が、影響を受ける/行動する/決定する立場に実際に置かれているか。

## 記録

主担当が担当先を指定する。`peer-reviews/<レビュー担当>-reviews-<作成担当>.json` と同名 `.md` を保存する。担当先のファイルは直接編集せず、修正は作成担当または主担当が行う。

JSON例：

```json
{
  "reviewer": "担当名",
  "author_group": "別担当名",
  "reviewed_ids": ["全件を読んだID"],
  "reviewed_count": 0,
  "scope": "読んだ本文・背景、既存との比較範囲、資料確認範囲を正確に記す",
  "findings": [
    {
      "id": "候補ID",
      "priority": "required または optional",
      "field": "question/detail/perspective/sensitivity/content_warning/novelty",
      "issue": "原文に即した問題点",
      "suggested_resolution": "具体的な修正文または差分を保つ条件"
    }
  ],
  "status": "reviewed_not_approved"
}
```

読んでいない問をreviewed_idsへ含めない。構造検証や自動キーワードチェックだけを全文レビューと呼ばない。すべての可能な二問比較や現実の会話テストを完了したとは書かない。重大な修正箇所は原文と理由を早めに主担当へ報告する。
